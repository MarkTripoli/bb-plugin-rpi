## Design specificity verdict

Authored, with a thin generic rim. The surfaces that carry the product's job are unmistakably this product: NeedsYouBand ranks failed above approval above ready and prints attentionText per row ("Finished its turn. Open to continue."); PhaseStrip is live (per-step count, "1 needs you / 2", "next", click-to-filter, PHASE_DESCRIPTIONS tooltip); SessionsTable's "What it wants" column plus effectiveStatus's "Done / Handed off: create pull request" encodes the fresh-context handoff nobody else has; CommentRail addresses comments to a session by name; NewTaskPage previews the step graph under the Workflow select. Status vocabulary is one table (statusMeta) and it shows in every surface identically.

Generic remnants: the List/Board toggle and TaskBoard (02-desktop-board.png shows two mostly empty columns above the fold), the WorkspacePanel data dump on the task Settings tab (05), and RpiDefaultsSettings' tables. None of these are wrong, they just could be any tracker.

## Cognitive load

Checklist (pass/fail, element):

1. One primary action per screen: PASS. Landing: Create task (only filled button). Task detail: Open current session. New task: "Create and start ..." filled, "Save as draft" outlined.
2. One status vocabulary everywhere: PASS. statusMeta drives StatusPill, sidebar glyph, phase strip tone, band; same words in all 13 shots.
3. No duplicated controls: PASS. Create task once, List/Board once (TasksSectionHeader), Open once per row (band row is itself the button; inner "Open" is a span).
4. No unexplained jargon at the point of decision: FAIL. "bypass permissions" has a tooltip but "Bypass" in the NewTaskPage Permissions select has none; "session" as a phase name in NeedsYouRow metaLine; "Kind: managed-worktree" in WorkspacePanel.
5. Hierarchy of three levels or fewer per page: FAIL on task detail. Panel tabs > task header > task tabs > phase strip > tip row > section header > table = 7 stacked bands before content (03, 09).
6. Progressive disclosure of secondary detail: PASS. Scratch in a popover, done sessions collapsed, Show N more, collapsible artifact groups, tips dismissible.
7. Consistent placement of back navigation: PASS. "All tasks" top-left on every task view; "< Artifacts 7" in stacked viewer.
8. Copy addressed to the reader: FAIL. TipsPanel inline row shows PHASE_TIPS verbatim ("Keep the parent thread as an orchestrator ... Commit only after the human approves"), which are skill rules for the agent shown to the human as tips (03, 09, 11).

Decision points with more than 4 visible options: 5 on the main flows. NeedsYouBand (7 rows, capped 8), TaskTable (6 rows), PhaseStrip (7 steps), ArtifactsPanel rail (7 files across 5 groups), RpiDefaultsSettings per-workflow table (5 rows x 2 selects). All are lists, not forks, so the load is scanning, not choosing; the ordering (rank then recency) does the work.

## Emotional journey

Opening after lunch (01, 10): Calm, then oriented. "Needs you 7" in yellow, zero red at the top-level nav, "0 sessions running. Press N to open the first item." One sentence tells you where you are. Then a small sour note: the first two rows are 3h and 4h old failures for phases the tasks have already moved past, and pressing N drops you into the stale worktree thread. The inbox opens on its oldest junk mail.

Launching a phase (06, 03): Confident. The New task form reads Where / How, the step preview updates as you change Workflow, the primary button names the first phase. The one hesitation: the label is "Create and start questions" (FIRST_SKILL_BY_WORKFLOW -> labelStep -> "questions"), which reads like a typo rather than a phase name. From a draft's detail page, Launch is filled and single.

Deleting (04 code path): Safe. ConfirmDialog on artifacts explains "It can be restored from this menu until the task is archived." Comments: "Also deletes any replies." Toast confirms. Context-warning rules (07) are the exception: trash icon, no confirm, no toast, built-in rules go into removedBuiltins with no visible way back.

Sending comments to an agent (04): Mostly reassuring, with a small vanish. The button says exactly what will happen ("Send 2 comments to Implementation"), the toast repeats it. But with the default "Send and resolve" and "Show resolved" unchecked, the comments disappear from the rail the instant you click. A first-time teammate will wonder whether they were sent or lost. And while there is nothing to send, the disabled button reads "Send 0 comments to Implementation", which is honest but awkward.

## What's working

1. Red now means failure and only failure. On 01 the only red is two Failed pills and one Failed sidebar glyph; ready_for_input is yellow with a speech-bubble icon (statusMeta "attention" tone, ROW_SHADE_CLASS deliberately excludes attention). The attention yellow reads as "your turn" in every context: band count, pills, sidebar chips, phase strip bar, TaskTable chip.
2. The inbox exists and is honest. NeedsYouBand plus attentionQueue plus effectiveStatus's superseded logic means "7" is a real number, each row says what the agent wants, and the whole row is one button to the thread. The phone version (10) is the best screen in the set: card per item, 36px tap target, no chrome.
3. PhaseStrip earns its place. It shows status per step, counts, "next", filters the table on click, defaults the filter to the current step, and carries a tooltip description per phase. "Sessions in implementation 2 / Show all 8" closes the loop.

## Priority issues

**P0. Failed rows point to a retry that may not exist, and stale failures cannot leave the inbox.**
What: attentionText for failed/lost says "Open it to see why, or retry." statusMeta hint says "retry it from Launch attempts." RecoverLaunchRow renders only for launch-attempt records (status failed with retryMarker null). A thread that failed during its run has no launch attempt to retry. Separately, effectiveStatus only supersedes a failed session when a newer session exists in the same or a later step; Formation Design's failed worktree (3h) is not superseded by plan attempt 6 (28m, an earlier step), so it sits at the top of the band and the sidebar, and N opens it.
Why it matters: The inbox's first two items on 01 are dead ends. A teammate will open, find nothing to retry, and come back to the same two red rows tomorrow. This directly breaks principle 1 (one step to act).
Fix: In NeedsYouRow for failed/lost, render the real actions inline: "Retry" when a retryable attempt exists, otherwise "Start fresh" (the existing fresh-session path) and "Dismiss" (mark the session acknowledged; a small persisted set like usePersistedSet or a server flag). Change attentionText to only say "or retry" when a retry is available.

**P1. The teaching layer is unreachable for keyboard and touch.**
What: Tooltip triggers on StatusPill, TaskMetaTerm, the sidebar status glyph (RpiThreadList sessionRow), artifact name (ArtifactRow), and the artifact title (ArtifactViewer) are plain spans. Radix Tooltip opens on focus or hover; a span cannot take focus and touch does not hover. The sidebar glyph has no text alternative at all: Icon plus color only.
Why it matters: PRODUCT.md's whole onboarding strategy is "teach in place." Sam gets no status hint and hears "Plan, attempt 6, 28m" with no status; Casey sees dotted underlines on 09 and 11 that do nothing when tapped.
Fix: Give TaskMetaTerm and StatusPill trigger spans tabIndex=0 (or make them buttons), add an sr-only status word next to the sidebar glyph, and for touch either open on tap (Radix Popover for the meta terms) or render the hint as visible helper text in compact mode.

**P1. Phase tips are addressed to the agent.**
What: TipsPanel inline shows PHASE_TIPS joined into one paragraph: "Keep the parent thread as an orchestrator. Use child implementer and reviewer threads before the commit gate. Commit only after the human approves commit and proceed." (03, 09, 11).
Why it matters: It occupies the most valuable line under the phase strip and tells the human what the agent will do, in the agent's voice. A new teammate reads "the human approves" and has to translate.
Fix: Either rewrite PHASE_TIPS as second-person next steps ("This phase commits only after you approve. When it finishes, open the session and press Proceed.") or drop the inline row and rely on PHASE_DESCRIPTIONS in the strip tooltip, which is already human-facing.

**P1. Phone artifact viewer header clips its controls.**
What: In ArtifactViewer the header is flex-wrap, but the inner group (version select + Preview + Raw) is a non-wrapping flex. The select's options carry "v1 · research-questions: RPI Cleanup", so on iPhone (12/13) "Preview" is half clipped and "Raw" is off-screen.
Why it matters: Casey cannot switch to Raw and cannot see the full version author; the panel's own stated width contract is broken on the exact device PRODUCT.md names.
Fix: Add flex-wrap to the inner controls group and shorten version option labels to "v1 · research-questions" (drop the task name; the user is inside the task). Consider `min-w-0 max-w-full` on the select.

**P2. Sidebar and panel disagree on how many sessions need you.**
What: RpiThreadList derives group rows from sidebar.threads (bb's recent-thread list) intersected with sessions; NeedsYouBand uses every session from listSessions. On 01 Formation Design shows badge 1 in the sidebar and 2 in the band and table.
Why it matters: Two counters with different numbers in the same viewport teach the user not to trust either.
Fix: Compute needsHumanCount in RpiThreadList from sessionsByTaskId (all sessions), not from the thread rows that happened to be in sidebar.threads, and show rows for missing threads with a muted "not in recent threads" glyph, or drop the badge count to match.

**P3. Task detail chrome before content.**
What: On 09 and 11 the reader passes panel tabs, All tasks, a 2xl title, a 6-term meta line, two buttons, three tabs, a 4-row phase strip, and the tip row before the first session. On phone the first session row starts around 1900px into a 2532px viewport.
Why it matters: The task page is where "act on the session that needs me" should complete; it is the slowest page in the set.
Fix: In compact mode collapse PhaseStrip to a single scrollable row (the compact min-w-[120px] wrap is what makes four rows), fold the meta line into a "Details" disclosure, and hoist the first needsHuman session as a single card above the strip.

## Persona red flags

**Alex (power user, wide desktop, 01 to 07)**
- NeedsYouBand: N opens queue[0], which on 01 is a stale Failed row; no j/k, no per-row shortcut, no way to skip.
- NeedsYouRow: navigates to the thread only; no path from the band to the task's Artifacts tab where the review actually happens.
- TaskTable: no sort, no filter, Updated column uses relativeTime only ("3h") with no absolute time on hover.
- TaskBoard (02): at ~1050px panel width only two columns fit above the fold and "Research & Design" is empty; the board hides the two columns that hold live work.
- SessionsTable: tooltip on the session name shows workingDirectory, but there is no copy action for the path and no thread id anywhere for CLI use.
- RpiDefaultsSettings (07): every ModelSelect fires setPrefs on change with no saved confirmation; five rows of "Default (from settings)" carry no indication of what the effective resolved model is.

**Sam (keyboard and screen reader)**
- StatusPill, TaskMetaTerm, ArtifactRow name, ArtifactViewer title, RpiThreadList glyph: Tooltip triggers on non-focusable spans, so the hint layer is silent.
- RpiThreadList sessionRow: status is conveyed by icon color only; no sr-only text, so "Plan, attempt 6, 28m" is read with no status.
- NeedsYouRow compact: `aria-label="Open session"` sits on a span with no role inside the row button; it is ignored by AT and the row already reads as the full sentence, which is fine, but the label is dead code.
- NewTaskPage Auto-advance: a toggle rendered as a button with no aria-pressed; state is color only.
- ArtifactsPanel groupHeader: the attention count chip for open comments is a Tooltip on a span; no text alternative for "3 open comments".
- Keep: rows use role="link" with tabIndex and Enter/Space handlers; tablist/tab/tabpanel wiring on both tab strips; PhaseStrip aria-current and aria-pressed; SplitHandle role="separator"; comment gutter focus-visible:opacity-100.

**Casey (phone, 10 to 13)**
- 10 landing: good. Every row is a 36px-plus tap target; status, task, phase, age, and what-it-wants fit without truncation.
- 11 task page: five dotted-underline meta terms invite a tap and do nothing on touch (Radix Tooltip). PhaseStrip wraps to four rows (compact min-w-[120px]); tip paragraph is five lines; "Sessions in implementation 2" is the last thing visible.
- 12/13 viewer: Preview clipped, Raw off-screen (ArtifactViewer header inner group not wrapping). Version select label is long enough to force it.
- 12/13: on phone ArtifactsPanel auto-selects the first artifact (refetch's setSelected fallback), so the user lands in the viewer and has to find "< Artifacts 7" to see the list. The list-first screenshot could not be captured for this reason.
- Comments on phone: CommentRail is rendered below the entire document in stacked mode; to send comments Casey scrolls past the whole artifact. No sticky send control.
- Positive: comment gutter is always visible and 36px at pointer-coarse; ConfirmDialog is the host's bottom-sheet on mobile.

## Minor observations

- "Create and start questions" (NewTaskPage primaryLabel) reads as an error; "Create and start research questions" or "Create and start" plus the step preview would read better.
- NeedsYouRow metaLine uses labelStep(label) ?? label ?? "session"; null-label sessions display "session · 31m" with no distinction from a named phase (SDK Dev and ctx-banner-test on 01).
- Yellow (attention tone) is also used for the open-comments count chip in ArtifactsPanel groupHeader. It is the only place yellow does not mean "a session needs you."
- Version meta line on 04: "9/6/2026 04:40 PM" is locale-formatted while the rest of the panel uses relativeTime.
- CommentThread anchors say "line N" but the anchor is a markdown block index (blockIndex + 1); a long paragraph is one "line."
- WorkspacePanel on the Settings tab mixes ready-state ("ready", "managed-worktree") with debugging fields ("Setup outcome: no provisioning events", "No workspace config found.") in the same visual weight.
- TaskDetailPage title is text-2xl; NewTaskPage h1 is text-lg; RpiDefaultsSettings h2 is text-sm. Three page-title sizes.
- Table headers keep text-[11px] uppercase tracking-[0.2em]; every other label in the panel is sentence case. Defensible as a table convention, but it is the last remaining tracked-uppercase style.
- Drafts tab is a filter presented as a sibling of Tasks, while Tasks already includes drafts (TaskTable shows the SDK Dev draft in the list and the board's Todo / Draft column).
- RpiThreadList renders Tooltip without a TooltipProvider in its own tree (providers exist in RpiPanel, ArtifactsPanel, header action, composer banner). It renders on 01, so the host must supply one; worth confirming that is a contract, not luck.
- Context-warning rule delete (RpiDefaultsSettings) is the one destructive action without ConfirmDialog or toast.
- "Send 0 comments to Implementation" as the disabled label; "Nothing to send" would be kinder.

## Questions to consider

1. Should a failed session that the task has visibly moved past (an earlier step re-run, or any newer session in the task) be treated as superseded by effectiveStatus, or does a failure need an explicit human acknowledgment before it leaves the inbox?
2. Is the task detail page's Sessions tab still the primary way to "act on a session," or has the band plus the composer banner made it a history view? If the latter, the phase strip and tips can shrink and the page can lead with Artifacts.
3. Tooltips are the whole onboarding strategy. Is the team willing to make every hinted term focusable and tap-openable (a small Popover instead of Tooltip on touch), or should compact mode render hints as visible helper text instead?
